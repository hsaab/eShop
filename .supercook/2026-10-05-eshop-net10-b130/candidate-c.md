# Candidate C: eShop net8.0 to net10.0 dry run

## Approach

Ship the dry run as one commit on `publix-dryrun-net10` and one pull request against `release/8.0` at `f236952`. The SDK pin, every `net8.0` target string, and the package versions the design names move in that same change, and the only code edits are the ones `dotnet build eShop.Web.slnf` then reports. The whole upgrade fits in one pull request. `release/8.0` stays at `f236952`, and the pull request is not merged.

## Why this over the obvious alternative

The obvious alternative is three small commits: target frameworks, then `Directory.Packages.props`, then compile fixes, with the MAUI projects left for a follow-up. Those commits do not restore on their own. Setting `AspireVersion` to `13.6.0` while `Microsoft.Extensions.ServiceDiscovery` and `Microsoft.Extensions.ServiceDiscovery.Yarp` still use `$(AspireVersion)` asks NuGet for a 13.x package that does not exist. Retargeting to `net10.0` without the design's package moves fails restore. Aspire 13.6.0 then fails to compile the Aspire 8 calls in `Program.cs`. A commit that does not restore or build is not a slice. The design already rejected staying on Aspire 9.5.2, copying `main`'s `AppHost.cs` rewrite, and retargeting only the solution filter. This plan follows that, in one review.

## Risks

- Aspire 13.6.0 rejects the Aspire 8 hosting calls. Early warning: the first `dotnet build eShop.Web.slnf` errors in `Program.cs` or either `*ApiFixture.cs` on `DistributedApplication.CreateBuilder` or a resource builder method.
- The net10 SDK promotes warnings and `TreatWarningsAsErrors` fails the build across many files. Early warning: errors in projects that do not reference Aspire, reported as analyzer codes rather than missing types.
- Docker is missing, so the functional fixtures never start Postgres. Early warning: `docker info` fails.
- `Pgvector.EntityFrameworkCore` 0.2.1 does not compile against EF Core 10. Early warning: a compile error that names that package. Move only that pin to `0.3.0`.
- Another package still pinned at 8.x has no net10 asset. Early warning: NU1202, NU1102, or a missing target framework during restore. Move only the package the error names.
- A ServiceDefaults edit made for a `10.0.12` signature also changes token checks. Early warning: the diff touches the authority, the audience, or the HTTPS metadata requirement.
- The Maui `10.0.110` pins are not built on this agent. Early warning: this Linux build stays silent on `ClientApp`, `HybridApp`, and `ClientApp.UnitTests`, which says nothing about a later Windows build.

## Least sure about

Whether `src/eShop.AppHost/Program.cs` can take Aspire 13.6.0 as a small edit to the existing calls. I would change my mind if the compiler errors require a new entry-point type, a generated host model, or a file named `AppHost.cs` before the AppHost project will build. Stop there and report that the surgical fix is not available. Porting `main`'s `AppHost.cs` stays out of the dry run.
